# seqattn-core v0.3.0-alpha.4

Date: 2026-08-28

This alpha separates optional multi-GPU execution from the single-GPU core and
adds explicit MiniMax-H3 materialized and QKV-recompute runner contracts.

Packaging changes:

- `seqattn-core` no longer ships or exports `MultiGpu*` schedulers, runners, or
  statistics;
- the separate `seqattn-multigpu` distribution contains static and dynamic
  scheduling plus the materialized-QKV multi-GPU H3 runner;
- both distributions use version `0.3.0a4`, and the plugin requires exactly
  `seqattn-core[dit]==0.3.0a4`;
- `seqattn_core.features` discovers optional plugins through entry points and
  reports an explicit feature-not-installed error when no provider exists.

DiT API changes:

- `H3MaterializedRunner` uses sequence-sized pinned host Q/K/V;
- `H3RecomputeRunner` uses two pinned hidden buffers and regenerates Q and K/V
  from an immutable source buffer for each block;
- `H3MaterializedProjection`, `H3RecomputeProjection`, and `H3BlockOps` keep
  weight and consumer leases separate, and the attention epilogue receives the
  residual hidden host tensor explicitly.

Compatibility:

- Python 3.10 or newer and PyTorch 2.5 or newer remain supported;
- the optional `seqattn-multigpu` plugin must exactly match core version
  `0.3.0a4`;
- existing consumers must migrate H3 callbacks to the explicit materialized or
  recompute projection contracts before updating their immutable core pin.

Validated configuration:

- NVIDIA RTX 5090 GPUs with CUDA 12.8, PyTorch `2.10.0+cu128`, Python 3.12.3,
  and the NVIDIA NGC 26.01 runtime image;
- core suite: all 99 tests passed with two GPUs exposed, including all 7
  two-GPU pipeline tests;
- optional multi-GPU plugin: 30 tests passed after installing the built
  `seqattn-multigpu-0.3.0a4` wheel with two GPUs exposed;
- Ruff lint and format checks passed, and source distributions plus wheels were
  built successfully for both `seqattn-core` and `seqattn-multigpu`;
- MiniMax-H3 consumer defaults remain `qkv_tile_tokens = 4096` and
  `mlp_tile_tokens = 4096`; deployment-specific Q and K/V chunks still require
  topology-specific calibration.
