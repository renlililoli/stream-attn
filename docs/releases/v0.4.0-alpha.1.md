# seqattn-core v0.4.0-alpha.1

Date: 2026-09-02

This alpha introduces model-specific single-GPU DiT orchestration for
MiniMax-H3, Wan, and LTX2, plus an explicit approximate Sol-style streaming
attention mode for MiniMax-H3. Model weight preparation and lifecycle policy
remain consumer-owned.

User-visible changes:

- DiT integrations live under `seqattn_core.dit.minimax_h3`, `.wan`, and
  `.ltx2`, with explicit materialized-QKV and recomputed-QKV runners;
- projected and recomputed self/cross attention share common mechanisms while
  Wan and LTX2 retain readable model-order control flow;
- MiniMax-H3 accepts `attention_mode = "dense"` or `"sol_streaming"`;
- `sol_streaming` performs a per-segment K/V summary pass, then routes 64-token
  blocks to exact attention or a K-centroid/V-sum approximation;
- exact prefixes apply to both Q and K/V blocks and round outward to 64 tokens;
- the default Sol policy keeps the first 20% of denoising steps and first two
  H3 blocks dense, with `tau = 1.0` afterward;
- materialized and recompute Sol execution share the resolved dense
  `CudaWorkspace` and single-flight lock instead of allocating parallel runtime
  stacks;
- recompute exposes a package-internal source-executor hook so dense and Sol
  policies reuse the same direct-write Q/K/V source and recovery contract;
- Sol preprocessing and streamed online-softmax updates are split into two
  cohesive Triton kernel modules;
- `seqattn_core.sparse` exports the Sol plan, runner, statistics, and semantic
  reference without adding sparse symbols to the core root or multi-GPU bridge;
- the optional `sparse` install extra declares the Triton dependency;
- a standard Apache-2.0 `LICENSE` is now included in source and wheel artifacts.

Sol V1 contract:

- single GPU, CUDA SM80 or newer;
- BF16, head dimension 128, and equal Q/KV head counts;
- non-causal self-attention with packed-segment support;
- explicit denoising step, block index, and per-segment exact-prefix metadata;
- unsupported contracts and insufficient workspace fail without silent dense
  fallback;
- every resident Q chunk still scans or projects all K/V, and each segment adds
  one complete summary prepass;
- recompute mode performs one extra complete K/V projection pass for summary
  creation;
- this release makes no end-to-end speedup claim.

The routing design is informed by NVIDIA Sol-Attn in Sol-Engine and the
Sol-Attention paper, arXiv:2607.24027. SeqAttn independently adapts the algorithm
to resident-Q, streamed-K/V execution and does not vendor the upstream
architecture-specific kernels.

Compatibility:

- this release intentionally breaks the alpha.4 DiT import and configuration
  layout;
- callers must replace `build_plan()` with `build_attention_plan()` and pass
  the resolved plan directly to reusable runners;
- Sol is selected by H3 `attention_mode`, not by the dense backend enum;
- sparse H3 consumers must install `seqattn-core[sparse]` and provide the new
  `H3DenoisingStep`, `block_index`, and `exact_prefix_tokens` metadata;
- `seqattn-core` and `seqattn-multigpu` must use version `0.4.0a1` and the same
  immutable release commit; Sol V1 is not exposed through the plugin API;
- core continues to exclude ComfyUI loaders, node classes, checkpoint
  preparation, and model-weight eviction policy.

Validation completed in `minimax-h3-seqattn:checks` on GPU 0, an NVIDIA GeForce
RTX 5090 (SM120), with PyTorch `2.10.0+cu128` and Triton `3.6.0`:

- complete single-GPU core suite: `187 passed, 1 skipped`; the skipped test
  requires two CUDA devices;
- focused Sol and H3 integration suite: `33 passed`;
- `ruff check .`, `ruff format --check .`, and `git diff --check` passed;
- source distribution and wheel built successfully with the sparse modules and
  Apache-2.0 license included;
- a clean container installed the wheel, observed the `sparse` extra, and
  imported `seqattn_core.sparse` successfully;
- independent-process operator sanity points at 4096 tokens, 8 heads, BF16,
  head dimension 128 measured median wall times of 5.80 ms for dense Triton,
  7.49 ms for Sol with all-exact routing, and 7.33 ms for `tau=1.0`; the latter
  had 19.83% exact route density and does not establish a speedup.

Publishing still requires an immutable release commit, remote annotated tag,
GitHub prerelease, and clean commit-archive installation verification at that
exact commit.
