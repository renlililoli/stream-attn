# seqattn-core v0.4.0-alpha.1

Date: 2026-09-02

This alpha introduces model-specific single-GPU DiT orchestration for MiniMax-H3,
Wan, and LTX2 while keeping model weight preparation and lifecycle policy in the
consumer.

User-visible changes:

- DiT integrations now live under `seqattn_core.dit.minimax_h3`, `.wan`, and
  `.ltx2`;
- Wan and LTX2 provide materialized-QKV and recomputed-QKV execution policies;
- exact projected cross-attention supports independent query and context hidden
  feature contracts;
- model configuration uses consistent `execution_mode`,
  `projection_tile_tokens`, and FFN tile naming;
- repeated runner calls are single-flight and recover persistent CUDA workspaces
  after callback or output-validation failures;
- recomputed self/cross attention now report avoided raw-attention host traffic
  at the projection runner boundary, independent of the calling DiT model;
- `build_attention_plan()` replaces `build_plan()`, and reusable streaming and
  projected runners now consume the resolved plan without a second runtime
  attention config;
- projection self/cross paths share materialization and recompute mechanisms,
  while Wan/LTX2 retain explicit model-order Python control flow;
- multi-GPU planning is separated from streaming execution while preserving the
  package-root API;
- obsolete `seqattn_core.storage.qkv` and private direct-I/O compatibility
  aliases were removed; import NVMe store types from `seqattn_core.storage` or
  the core package root;
- package metadata uses the SPDX license expression accepted by current
  setuptools without deprecated license fields or classifiers.

Compatibility:

- this release intentionally breaks the alpha.4 DiT import and configuration
  layout;
- direct imports from `seqattn_core.storage.qkv` or plan symbols from
  `seqattn_multigpu.streaming` must move to the documented package-root APIs;
- callers must replace `build_plan()` with `build_attention_plan()` and pass
  only the resulting plan to `StreamingAttentionRunner`;
- `seqattn-core` and `seqattn-multigpu` must both use version `0.4.0a1` and the
  same immutable release commit;
- core continues to exclude ComfyUI model loaders, node classes, weight
  preparation, and eviction policy.

Validation completed for this release candidate in the canonical NGC 26.01
CUDA image with PyTorch `2.10.0+cu128`:

- complete two-GPU core suite: `162 passed`;
- installed core plus `seqattn-multigpu` plugin suite: `34 passed`;
- focused projected cross-attention and model-specific DiT regression suite:
  `66 passed`, with one two-GPU test skipped in the single-GPU focused run;
- `ruff check .`, `ruff format --check .`, and `git diff --check` passed;
- source distributions and wheels built successfully for both packages without
  setuptools deprecation warnings.

Publishing still requires an immutable release commit, remote annotated tag,
GitHub prerelease, and clean archive-install verification at that exact commit.
